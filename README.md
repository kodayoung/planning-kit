# 기획 도구 (planning-kit)

제품 프론트 **화면 위에 기획안을 얹어 보는 도구**입니다.
프론트 레포는 한 글자도 고치지 않습니다. 개발 작업과 충돌하지 않습니다.

```
브라우저 ──▶ 기획 도구(localhost:4000) ──▶ 프론트 개발 서버(3000) ──▶ 백엔드
                 │
                 ├─ 아직 없는 기능 → 가짜 응답으로 대신 답함
                 ├─ 화면 위에 기획안 설명 스티커
                 └─ 요소·범위에 코멘트 → 깃랩 이슈로 저장
```

## 할 수 있는 것

| | |
|---|---|
| **기획안 읽기** | 화면 요소를 누르면 그 항목의 **기획안 원문**이 그대로 뜹니다. 번호는 피그마 기획안의 그 번호입니다 |
| **코멘트** | 요소를 찍거나 **드래그로 범위를 잡아** 코멘트를 남깁니다. 깃랩 이슈에 저장되고 @멘션·답글·해결 처리가 됩니다 |
| **목업** | 백엔드에 없는 기능을 가짜 데이터로 미리 눌러봅니다. 로딩·에러 화면도 재현됩니다 |
| **버전** | 보관해둔 과거 기획안으로 화면을 되돌려 봅니다 |

## 처음 한 번

### 1. 준비물

- **Node 22 이상** ([nodejs.org](https://nodejs.org))
- **프론트 레포**가 이미 받아져 있고 `pnpm dev` 가 도는 상태
- **기획안 KB** (피그마 기획안을 화면 단위 JSON 으로 추출한 폴더). 없으면 `snapshots/` 보관본으로 대신합니다

### 2. 설치

```bash
npm install
npm run setup
```

`npm run setup` 은 **고쳐주지 않고 무엇이 왜 필요한지만 알려줍니다.** 각자 PC 경로가 달라서요.
빨간 `✗` 가 없으면 시작할 수 있습니다.

### 3. `.env` 채우기

`npm run setup` 이 `.env` 를 만들어 둡니다. 본인 PC 에 맞게 고치세요.

| 항목 | 무엇 | 없으면 |
|---|---|---|
| `FRONT_URL` | 프론트 개발 서버 주소 (보통 `http://localhost:3000`) | 화면이 안 뜹니다 |
| `KB_DIR` | 기획안 KB 폴더. **쉼표로 여러 곳** 적을 수 있습니다 | 설명이 안 뜹니다 |
| `FRONT_REPO` | 지금 보고 있는 프론트 레포(워크트리) 경로 | 툴바에 브랜치가 안 뜹니다 |
| `CAPTURE_MAP` | KB 의 `capture-map.json` (화면 주소 지도) | `npm run gen` 이 안 됩니다 |
| `CHECK_ID` / `CHECK_PW` | 본인 테스트 계정 | `npm run check` 가 로그인 뒤 화면을 못 봅니다 |
| `GITLAB_TOKEN` | **본인** 깃랩 토큰 (아래) | 코멘트만 꺼집니다 |
| `GITLAB_PROJECT_ID` | 코멘트를 저장할 깃랩 프로젝트 | 〃 |
| `GITLAB_DEFAULT_ISSUE` | 스펙이 없는 화면의 코멘트가 갈 이슈 번호 | 그 화면에서 코멘트를 못 답니다 |

> **`.env` 는 커밋되지 않습니다.** 토큰·비밀번호는 여기에만 두세요.

### 4. 깃랩 토큰 발급 (코멘트를 쓸 때만)

**각자 본인 계정으로** 발급하세요. 남의 토큰을 쓰면 코멘트 작성자가 그 사람으로 찍힙니다.

깃랩 → 우측 상단 프로필 → **Edit profile** → **Access tokens** → 새 토큰

**Project access** 에서 코멘트를 저장할 프로젝트를 고르고, 아래 권한을 체크하세요.

| 권한 | 왜 |
|---|---|
| `Project: Read` | 프로젝트 확인 |
| `Work Item: Read` | 코멘트 읽기 |
| `Work Item: Create` | 코멘트·답글 등록 |
| `Member: Read` | `@` 멘션 자동완성 |
| `Label: Read` | 라벨 확인 |

발급한 값을 `.env` 의 `GITLAB_TOKEN=` 에 넣으세요.

> **주의.** PC 사용자 환경변수에 다른 `GITLAB_TOKEN` 이 이미 있을 수 있습니다.
> 도구는 `.env` 를 우선하고, 첫 코멘트를 등록할 때 **실제 작성자가 누구인지 콘솔에 확인**해 줍니다.
> `.env` 에 `GITLAB_EXPECTED_USER` 를 적어두면 다른 계정일 때 경고가 뜹니다.

## 매번 쓰는 법

터미널 두 개가 필요합니다.

```bash
# 1번 터미널 — 프론트 레포에서
pnpm dev

# 2번 터미널 — 기획 도구에서
npm run dev
```

브라우저에서 **`http://localhost:4000`** 을 엽니다. 평소 화면과 똑같이 로그인해서 쓰면 됩니다.

### 화면에서

| 키 | 하는 일 |
|---|---|
| (그냥 씀) | 제품 화면 그대로. 스티커 없음 |
| `S` | **스펙 모드** — 기획안 스티커가 뜨고, 누르면 설명 카드. 원래 동작은 막힙니다 |
| `C` | **코멘트 모드** — 요소를 클릭하거나 **드래그로 범위**를 잡아 코멘트 |
| `Alt` + 클릭 | 모드를 바꾸지 않고 설명만 보기 |
| `Esc` | 사용 모드로 돌아가기 |

**스티커 색**

| | |
|---|---|
| 보라 숫자 | 기획안 항목 (숫자 = 기획안의 그 번호) |
| 회색 `＋` | 기획안에 없는 항목 |
| 하늘 `💬` `▭` | 코멘트를 단 요소 / 범위 |
| 빨강 | 화면에서 그 요소를 못 찾음 (화면이 바뀐 것) |
| 주황 배지 | 미해결 코멘트 수 |

툴바 왼쪽에 **지금 보고 있는 프론트 브랜치**가 뜹니다. 다른 사람과 얘기할 때 같은 갈래를 보고 있는지 먼저 확인하세요.

## 명령 모음

| 명령 | 하는 일 |
|---|---|
| `npm run dev` | 기획 도구 실행 |
| `npm run setup` | 준비 점검 |
| `npm run check -- --list` | 메뉴별 점검 명령 목록 |
| `npm run check -- "설정 >"` | 그 메뉴 화면들의 스티커가 제자리인지 점검 |
| `npm run gen` | 기획안 KB 로 스펙 파일 다시 만들기 |
| `npm run snapshot "이름"` | 지금 기획안 전체를 버전으로 보관 |
| `npm run snapshots` | 보관된 버전 목록 |
| `npm run snapdiff -- A B` | 두 버전 차이 |
| `npm run bundle` | 공유 링크용 묶음 만들기 (아래) |

> **점검은 메뉴 단위로.** 화면 수십 개를 한 번에 돌리면 뒤로 갈수록 화면이 느려져
> 멀쩡한 요소가 "못 찾음" 으로 찍힙니다.

## 공유 링크 (아무것도 안 받고 보게 하기)

동료한테 이 도구를 통째로 받게 할 수는 없습니다. 그래서 **주소 하나**로 보는 길을 따로 둡니다.

```bash
npm run bundle     # 기획 건별로 화면을 빌드해서 public/ 에 담습니다
npm run deploy     # 깃랩 Pages 에 올립니다
```

동료는 **설치도 clone 도 없이** 주소만 엽니다.

### 기획 건을 여러 개 담습니다

기획 건마다 프론트 갈래가 다릅니다. 갈래가 다르면 **화면 자체가 다른 프로그램**이라 하나로 합칠 수 없습니다.
그래서 건마다 주소 아래 자기 자리를 주고, 화면 위 **보라색 칸**에서 옮겨 다닙니다. 링크는 하나입니다.

```yaml
# plans.yaml
- slug: new-feature                 # 주소에 쓰일 이름 → /new-feature/
  title: 새 기능 기획               # 툴바에 보일 이름
  repo: C:/…/feat-new-feature       # 그 갈래 워크트리
  start: /settings                  # 고르면 열릴 화면
```

`npm run bundle` 이 각 갈래를 알아서 빌드합니다 (건당 1~2분). 워크트리에 `pnpm install` 이
안 돼 있으면 그 건만 건너뛰고 알려줍니다. 다시 빌드하지 않으려면 `npm run bundle -- --skip-build`.

### 코멘트는 각자 자기 계정으로

링크에는 토큰을 넣지 않습니다. 넣으면 링크를 받은 누구나 그 계정으로 깃랩에 글을 쓸 수 있으니까요.
대신 **보는 사람이 자기 깃랩 계정으로 한 번 로그인**하고, 그 사람 브라우저 안에서만 사는
출입증으로 코멘트를 씁니다. 작성자가 본인으로 정확히 찍힙니다.

그러려면 깃랩에 애플리케이션을 **한 번만** 등록해 두어야 합니다.

깃랩 → 프로필 → **Edit profile** → **Applications** → 새 애플리케이션

| 칸 | 넣을 값 |
|---|---|
| Name | `기획 도구` |
| Redirect URI | 배포된 링크 주소 (예: `https://<그룹>.gitlab.io/<프로젝트>/`) |
| Confidential | **체크 해제** |
| Scopes | `api` |

> `Confidential` 을 꼭 풀어야 합니다. 브라우저에는 비밀값을 둘 수 없어서,
> 비밀값 없이 도는 방식(PKCE)으로 로그인하기 때문입니다.

등록하면 나오는 **Application ID** 를 `.env` 에 넣고 다시 구우면 됩니다.

```
GITLAB_OAUTH_CLIENT_ID=<Application ID>
PAGES_URL=<Redirect URI 와 똑같은 주소>
```

### 링크로 보는 것과 도구로 보는 것의 차이

| | 도구 (`npm run dev`) | 공유 링크 |
|---|---|---|
| 준비물 | Node · 프론트 레포 | 브라우저만 |
| 화면 데이터 | 진짜 백엔드 | **미리 받아둔 응답만** |
| 기획안 | 켤 때마다 최신 | 구운 시점 기준 |
| 코멘트 | 됨 | 됨 (로그인 한 번) |
| 버전 되돌려보기 | 됨 | 안 됨 |

### 실패 화면도 링크에서 눌러볼 수 있습니다

기획안에는 "목록이 비면 안내를 띄운다" 라고 적지만, **진짜 그렇게 뜨는지는 눌러봐야 압니다.**

`mocks/routes.yaml` 에 같은 주소로 여러 경우를 적어두면, 링크를 받은 사람이 **화면 위 초록색 칸에서 직접 골라**
볼 수 있습니다. 성공 → 빈 목록 → 서버 오류 → 로딩 3초. 고르면 화면이 새로 뜹니다.

```yaml
- name: 공지 목록 · 성공                   # 가운뎃점 앞 = 묶음, 뒤 = 경우 이름
  method: GET
  path: /api/example/notices
  file: example/notices.json
  enabled: true                            # 링크를 열었을 때 처음 보이는 것

- name: 공지 목록 · 서버 오류
  method: GET
  path: /api/example/notices               # 주소가 같으면 같은 묶음
  file: example/error.json
  status: 500
  enabled: false                           # 링크에는 실려 가고, 골라야 보입니다
```

> 실패 화면을 보여주려고 다시 구워 올릴 필요가 없습니다. 경우를 전부 실어 보냅니다.

> **받아둔 응답이 없는 화면은 "오류가 발생했습니다" 가 뜹니다.**
> `.env` 의 `MOCK_MODE=record` 로 도구를 띄우고 그 화면들을 한 번씩 돌면 자동으로 모입니다.

## 자주 생기는 문제

**화면이 안 뜨고 "프론트 개발 서버가 꺼져 있습니다" 가 나옵니다**
프론트 레포에서 `pnpm dev` 를 먼저 실행하세요. 기획 도구는 그 앞에 서는 창구일 뿐입니다.

**보고 싶은 버튼·화면이 없습니다**
기획 도구는 *데이터*를 가짜로 만들지 *화면*을 만들지 않습니다.
그 기능이 든 **브랜치로 프론트 서버를 띄워야** 합니다. 워크트리마다 `pnpm install` 이 따로 필요합니다.

**스티커가 빨간색입니다 (요소를 못 찾음)**
화면이 바뀌어 기획안 항목과 안 맞는 상태입니다. `npm run check -- "메뉴 >"` 로 목록을 뽑고,
Claude Code 에 *"check 결과 보고 locator 고쳐줘"* 라고 하면 됩니다.

**코멘트 칸에 "깃랩 코멘트: 꺼짐" 이 뜹니다**
`.env` 의 `GITLAB_TOKEN` / `GITLAB_PROJECT_ID` 를 확인하세요. `npm run setup` 이 무엇이 빈지 알려줍니다.

**코멘트 작성자가 내가 아닙니다**
사용자 환경변수의 다른 토큰이 쓰인 경우입니다. `.env` 의 `GITLAB_TOKEN` 을 본인 것으로 채우고
기획 도구를 다시 실행하세요.

**설명이 옛날 내용 같습니다**
툴바 드롭다운이 **과거 버전**으로 되어 있는지 보세요. 과거를 보는 중이면 툴바가 주황색으로 바뀝니다.
`지금 기획안` 으로 되돌리면 됩니다.

**목업이 안 먹습니다**
`.env` 의 `MOCK_MODE` 가 `off` 인지 보세요. `partial` 이어야 `mocks/routes.yaml` 에 적힌 것만 가짜로 답합니다.

## 폴더

| | |
|---|---|
| `proxy/` | 중간 창구 서버 |
| `overlay/` | 화면에 얹히는 스크립트 (`locator.js` = 요소 찾는 규칙, 점검 스크립트도 이 파일을 씁니다) |
| `specs/` | 화면별 요소 정의. `generated/` 는 `npm run gen` 이 덮어씁니다 |
| `mocks/` | 가짜 응답 (`routes.yaml` 이 규칙) |
| `snapshots/` | 보관된 기획안 버전 |
| `scripts/` | 점검·생성·보관 명령 |
| `docs/` | 이 도구의 구축 가이드 |
